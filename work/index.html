NVIDIA · Senior System Software Engineer · Jan 2025 - Jun 2026

CASE STUDY

Windows CI with GPU support for PyTorch

Problem

PyTorch had no CI testing Windows with a GPU

My role

Led the design and development

Approach

Windows VMs in Kubernetes, jobs pulled by runners

Stack

KubeVirt · VFIO · QEMU · GitHub Actions

GitHub Actions

A workflow requests a Windows GPU run

Job service

Queues the job; a gateway screens it first

PULL

Runner pod

Asks for work over an outbound connection

Windows VM

KubeVirt with a VFIO GPU runs the tests

How it came together

  1. 1

    Prototype

    A Windows workflow on a private fork, running on one internal machine

  2. 2

    Sandboxed design

    Windows VMs inside Kubernetes pods instead of bare-metal servers

  3. 3

    GPU passthrough

    VFIO, KubeVirt and QEMU so each VM gets a real GPU

  4. 4

    On-demand VMs

    A custom Windows image and a fresh VM for each job

  5. 5

    Cluster operations

    Monitoring, logging and Kubernetes network policies

  6. 6

    End to end

    A GitHub workflow starts a VM and tests the PyTorch build on it

  7. 7

    Out-of-tree CI

    Redesigned the core service for PyTorch's out-of-tree model

  8. 8

    Windows on ARM

    The same CI on NVIDIA's unreleased WoA, with PyTorch core developers

  9. 9

    Security review

    STRIDE threat model, network policies and a pre-execution gateway

Also: telemetry dashboards from 10 min to under 1 s

Found the bottleneck in a Grafana and Prometheus pipeline and moved query execution to run asynchronously.
